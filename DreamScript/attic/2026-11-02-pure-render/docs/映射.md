# 剧本 ⇄ md 映射规范

这份文档定义两件事：剧本怎么落成 md，md 怎么变回剧本。规则全部对应到可执行的地址与操作（本 wt 的 `剧本.md` 就是按这份规范写的实例）。

## 1 元素表

| 剧本元素（$Type） | md 构造 | 值 |
|---|---|---|
| Title Page | 一级标题 + 题头 bullet | `- 编剧:` / `- 稿次:` / `- 日期:` |
| Scene Heading | 「场景 N」二级节 + 三个字段 | `- 内外:` / `- 地点:` / `- 时间:` |
| Action | bullet | `- 动作: …` |
| Character | bullet | `- 角色: MIA` |
| Parenthetical | bullet | `- 副语言: （紧张）` |
| Dialogue | bullet（同名多行 ⇒ 数组） | `- 台词: …` |
| Transition | bullet | `- 转场: CUT TO:` |
| Shot | bullet | `- 镜头: …` |
| General | bullet | `- 段落: …` |
| 逐字块（歌词 / 蒙太奇列表） | 带 tag 的代码块 | tag = `原样` |

四条规矩：

1. **一场戏 = 一个二级节**（节 = 子树）：可整章认领、可计数、可寻址。
2. **一个元素 = 一行**：值里不出现换行；多段用多条 `- 台词:`。
3. **类型住在 tag 里**：md 里只有标题 / bullet / 代码块 / 有序列表有 tag，段落没有 —— 用段落写动作，动作与镜头与段落三种就再也分不开。
4. **每条 `- 角色:` 开启一段 speech**，其后所有 `- 台词:` 都归它 ⇒ 连续台词 = 同一段的续行或多段；两次演讲必然写两次角色。无歧义。

## 2 文档骨架

```markdown
# LA LA LAND
- 编剧: Damien Chazelle
- 稿次: 第二稿

- 段落:
- 动作: Mia gathers her nerves. Gets up. And steps in.

## 场景 1
- 内外: 内
- 地点: AUDITION OFFICE
- 时间: 下午
- 镜头: WE RETURN to the AUDITION ROOM...
- 角色: MIA
- 副语言: （紧张）
- 台词: Here's to the ones who dream, Foolish as they may seem.
- 转场: CUT TO:
```

## 3 剧本 → md

两条入口，保真等级不同：

- **结构化入口**（DreamScript 的 `{$Type,_}` / FDX-JSON）：类型显式 ⇒ 无损迁移（除 slugline 拼写规范化）。
- **纯文本入口**（Final Draft 惯例）：启发式 ⇒ 规范化。识别规则：场景头（INT/EXT/内外景 + `- ` 时间段）· 角色（整行大写、短、前空行、后非场景头）· 副语言（整行圆括号且紧跟角色）· 转场（行尾 `TO:` 或 FADE IN/OUT）· 其余非空行 = 动作，空行 = 段落边界。

两条顺序规则：

- **元素序 = 树序**；slugline 不占元素位，它变成节边界（字段挂在节上）。
- 首条 slugline 之前的元素挂一级标题节下（题头字段之后）—— 场景外元素没有家，这是给它留的位置。`剧本.md` 里的 `- 段落:` / `- 动作:` 就是这种情况。

slugline 三分：内外（`INT.` / `EXT.` / `INT./EXT.` 前缀）+ 地点 + 时间（` - ` 之后那段）。

## 4 md → 剧本

- **屏幕**：排版件认领每个「场景 N」节（选择器 `..*[h2]`，path 门控 `/剧本.md::`），一节整章自画：slugline 大写、动作左对齐、角色居中、副语言缩进、台词缩进、转场右对齐；题头件认领一级标题。
- **文本导出**：同一份序列化器（树 → 元素序 → 文本），写到 `/导出/剧本.txt`；旧 `{$Type,_}` JSON 出口同源。
- **打印**：CSS mod（tag `print@css`）：Courier 12pt、Letter、场景头不与上文分离（`break-inside: avoid`）。宿主没有任何 print 规则 ⇒ 版式完全由这份 CSS 决定。
- **声明按类型过滤，不写名字**：`..*[h1]` / `..*[h2]` 稳；实测把一整条带空格的名字当选择器（`"LA LA LAND"`）会被拆成三段 `Drill` ⇒ **静默零命中**；名字后面跟了步（`"LA LA LAND"._b`）就正常。

## 5 保真分级

| 等级 | 内容 |
|---|---|
| 无损 | 元素类型、元素顺序、文本内容（逐字）、多段结构（按 `- 角色:` 分段） |
| 规范化 | slugline 拼写（重建为 `INT./EXT. 地点 - 时间`）· 纯文本入口的软换行合并 |
| 归一 | 行尾空白、段内多余空格 |
| 不保留 | 源文件的缩进 / 字体 / 分页 / 字数统计 |
- **两条闭合律（实测）**：文本档 `文本 → md → 文本` 逐行相同（42 行 · 0 差异，幂等）；JSON 档 `JSON → md → JSON` **逐字节相同**（19 段，含空元素）⇒ 要无损迁移走 JSON 档，要给人看/给 Final Draft 走文本档。
- **空元素**：`- 段落:`（空值，旧数据里的 `{$Type:'General'}`）在文本载体里不承载信息 ⇒ 文本导出主动跳过它；JSON 出口逐段带 `$Type`，原样保留。
- **文本载体会归一化的两处**：镜头行一律大写（`WE RETURN TO …`）；题头是「稿次 · 日期」一行，往返后归到 `- 稿次:`。要逐字保真走 JSON 档。

## 6 写回（编辑动作 → 地址）

| 动作 | 载荷 → 目标 |
|---|---|
| 改一句台词 | `"新台词" \| /> 该条地址 -f false` |
| 在这条之后插一条 | `"- 台词: …" \| +> 该条地址 -pj raw` |
| 删一条 | `-> 该条地址` |
| 改场景头字段 | `"下午" \| /> 字段节点地址 -f false` |
| 改类型 | `"镜头" \| /> 该条地址 -pj t` |
| 加一场戏 | 多行载荷 `\| +> /剧本.md:: -pj r` |

三条防护（防「静默写歪」）：**唯一落下**（同名 tag 必带序号）· **`-f false`**（目标不在就报错，不接骨新建）· **写前值对账**（防序号漂移）。写值 = 指节点 + 默认投影。

- **入口 + 内部 sel**：认领下来的子树里，形状由件自己定 —— 写回 = 入口地址（由形状派生，如 `/"场景 2"`）+ 内部选择器（如 `._b[b.t=="动作"][0]`）；序号与切片是 exec 侧的能力，`-pj` 三种面语义不变（实测）。
- **改类型 = 改 tag**：`-pj t` 一次写即可（实测：动作 → 镜头）。
- **载荷两个坑**（实测）：值里的换行用 `String.fromCharCode(10)` 造（字面反斜杠 n 会被多反转义一层）；引号**直接写裸引号**即可 —— 写成反斜杠转义反而会把反斜杠写进文档。
- **写回会「静默成功」**：地址畸形、载荷带多余换行这两类错，引擎都回 `mdio_success` 而实际没改（本项目实测三次）⇒ 写前值对账 + 写完读一眼，是这套写回模型的必需件，不是防御性编程。
- **「在某条之后插入」的落地写法**（本 app 用的那条）：读节体（`$ "节名" -pj ct`）→ 在锚点行后拼接新行 → 整节写回（`/> "节名" -pj ct`）。它只依赖 `$` 与 `/>` 两个原语，节内元素一条不多一条不少。

## 7 已知缺口（留作扩展）

- **双人对话**（并排两列台词）：旧模型无此类型；做法 = 在第二条角色 bullet 上加 `- 并排: 是`。
- **场景号（制作号）**：`- 号: 12A`，与节名里的序号分开，可锁定。
- **Shot 与 Action 在纯文本里同形**：默认按动作；要精确就走结构化入口。
- **蒙太奇 / 插入镜头**：多条 `- 镜头:` + `- 段落:`，或逐字块（tag = `原样`）。
