# 路由机制草案（一页）

> 状态：**草案**（结论页）。**权威关系：实现 > 本页 > `路由研究.md`（过程与证据）**；冲突时以实现为准，并回头修正本页与 note。
> 本页刻意不写声明节的标题字样（井号 + mods / match），以免被当作声明解析（已实测踩过）。

## 一句话

**声明住在每棵树自己的 `.mds/ui.md`；URL 的组合权归壳；router 只管各层内部的路由上下文。**

## 工具与语义（全部已验证；括号内为判据/实测出处）

| 能力 | 在哪 | 语义 | 验证 |
|---|---|---|---|
| `entry` 入口声明 | 每棵树自己的 `.mds/ui.md` 的 router 节 | 切到这棵树时先开哪个文档；可缺省 | 清单含本树 / 切树⇒直达 app |
| **每树记忆** | 宿主（`demo/src/entry.client.ts`，sessionStorage）| 这棵树"上次所在页"；离开记、回来优先，**没记忆才用 entry** | 切走再回来恢复 / 跨刷新持久 |
| `appRouter.hash` / `.path` | 壳注入（`ui_core/appRouter`，在 NodeView **使用点**创建）| 应用页内路由的两种表达（hash 不占 path；path 即真实路径）；**壳参数一律透传** | URL 保留壳参数 / 页内表达 |
| `appRouter.layerHost()` | 同上 | 壳提供面板容器 `#mdio-layer-host`（应用 portal 进来）| 容器由壳提供 |
| `createLayer({layer:{push:false,autoPush:false}})` | 应用侧（`@esmx/router` · 构建型 mod）| 层 = 隔离路由上下文；**父页面继续跑**；`push:false` ⇒ URL 不动 | 面板 4 条 |
| root / children（两级）| root 树 router 节 + 各树 entry | root 认领外壳并把各树当子路由；**wt 切换 = 壳的一次 URL 组合** | 壳切树 ⇒ URL 带 wt+app |

## 边界（保证什么、不保证什么）

- **保证**：URL 层的"页"（wt / app / 页内表达）与其**跨 wt 记忆**。
- **不保证**：应用内的**非 URL 状态**（草稿、滚动、未提交输入）—— 应用自决；想持久化可用同一 key 策略。

## 未决

1. router 节语法是否收敛（root/children/entry 之外，是否要子路由表）。
2. root 总 router 的声明形状（`root: mdio_ui` 是否要细化为槽位）。
3. 跨 wt 的**非 URL** 状态是否要机制化。

## 维护规则（承诺）

1. 改前自问：是否让这条线更清？——**md 文本 → 组件 → MST + 声明 → match 认领 → NodeView 渲染**。
2. 少碰官方件：能力在**使用点**创建；机制落**宿主装配点**；不碰共享 owner（ui_base）与无关 mod。
3. 构件必须 `ok = true`（构建失败会**静默保留旧产物**，实测踩过）。
4. 判据绿才算完；每步留证据在 note（小步追加 + 小查询校验）。

## ⚠ 修订中（2026-10-04 · 第 31 轮）

本页下方的"工具与语义表"里，**router 节的说法已被上游模型取代**：node / doc / wt 三档其实是**同一套认领规则**（match/vis 就是 node 档的路由），区别只在"施与方式"（node 档全量遍历；wt/doc 档由 URL 指针选一个）。
